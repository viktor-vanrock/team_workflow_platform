# UX-аудит: до изменения

Дата: 2026-09-08. Метод: осмотр действующего local pilot в браузере, анализ App и QA/project/queue компонентов, независимое исследование маршрутов и тестов. Это экспертный аудит, не измерение поведения группы пользователей.

| Приоритет | Наблюдение и место | Влияние | Решение |
|---|---|---|---|
| P1 | `App.tsx`: первым показан «Сквозной каркас ядра расширений», Dummy и Mock Hub; браузер подтвердил перегруженный первый экран | Непонятно назначение и главное действие | Вход с описанием роли, главная с действиями; demo отдельно |
| P1 | `App.tsx`: нет nav, pathname читается напрямую, ссылки перезагружают сессию | Основные разделы невозможно обнаружить | Общая nav/history, выделение раздела, сохранение входа при переходах |
| P1 | `intake.tsx`: изменяемая форма рядом с confirmation старого draftId | Отправляется содержание, отличное от видимого | Заполнение → сохранённое резюме → отправка → результат |
| P1 | `contribution.tsx`: автоматически выбирается первый запрос; вкладка «Запрос» создаёт другой | Неясно, с каким объектом работает пользователь | Отдельные создание и список, выбор по названию, явный detail |
| P1 | Вложенные Sessions/Evidence запоминают props ID только на mount | Смена выбора может оставить старого адресата | Key по context/request, очистка summary, игнорирование старых ответов |
| P2 | `App.tsx`: старая overview остаётся при смене персоны | Старые данные другого контекста могут остаться на экране | Размонтирование рабочей области при exchange, чистая сессия при ошибке |
| P2 | Intake показывает idempotency key, «устойчивый обработчик», timeout как провал | Непонятно, создан ли запрос и можно ли повторять | Смысловые processing/success/error states, проверить статус того же draft |
| P2 | Queue/каталог: IDs, hashes, projections; пустой экран без действия | Неясен следующий шаг | Пояснения, empty states, служебные детали свёрнуты |
| P2 | Buttons с tab role без tabpanel/keyboard; голые select; мелкие элементы | Неравномерность UI, сложность клавиатурного выбора | Общий theme, labels, MUI tabs, focus, адаптивный shell |
| P3 | Глубокие административные формы: exact refs/hashes и команды настройки | Требуют знания инфраструктуры | Понятный административный вход/пояснения; глубокая переработка этих контрактов отдельная работа |

Сохраняются серверные grants, Jira authority, явная отправка, scope и immutable history. UI не обещает readiness для DRAFT/MANUAL_ONLY. Полное изменение корпоративных экранов и бизнес-форм onboarding не входит в реализацию 013.
