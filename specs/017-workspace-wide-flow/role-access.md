# Проверка доступов по ролям

Дата: 2026-09-09. Проверяется локальный стенд и реальные серверные назначения, не только подписи меню.

| Роль и люди | Что доступно | Что ограничено |
| --- | --- | --- |
| Администратор · 1 / · 2 | Одинаковые функции проектов, доступов, интеграций, проверки подключений; чтение общей очереди и запросов | Нет планирования/исполнения QA только на основании административной роли; нельзя согласовать своё действие |
| Заказчик | Общие запросы и очередь; создание, подтверждение и уточнение запроса; решения по входящим обращениям | Нет администрирования, изменения порядка, исполнения проверок и подписи заключения |
| Исполнитель QA · QA 1 / QA 2 | Оба работают с ALPHA/BETA; проверки, результаты, замечания, черновики дефектов, подпись QA; подготовка автоматических сеансов | Нет администрирования и управления порядком очереди; нельзя независимо согласовать собственное действие |
| Руководитель QA | Общая очередь, изменение порядка, чтение запросов и результатов; согласования риска/заключения/закрытия в пределах разрешений | Нет создания запроса, планирования или запуска автоматического сеанса; исполнение QA не выдаётся вместе с ролью лида |
| Читатель · 1 / · 2 | Одна роль reader, запросы, очередь, проекты, история Hermes, уведомления; доступны только разрешённые данные | Все команды изменения отключены или скрыты. У первого читателя потолок INTERNAL (ALPHA), у второго RESTRICTED (ALPHA/BETA); объединение роли не повышает персональную классификацию |
| Технический писатель | Предметная область документов: создание, свои черновики, отправка на ревью | Нет QA-разделов и утверждения документов |
| Лид технических писателей | Предметная область документов: просмотр, ревью, возврат и утверждение | Нет QA-разделов и авторского создания документов |
| Сервисная запись | Диагностика, обзор и справка | Нет человеческих QA-экранов; сервер отклоняет вызов QA от SERVICE |
| Пользователь другой области | Только собственная область DELTA и её разрешённые данные | Нет ALPHA/BETA, каталога основной команды и административных экранов |

Права берутся из проекта открытой сущности; объединение прав в меню не разрешает действие в другом проекте. Сервер повторно проверяет членство, назначения, entitlement, DENY и классификацию. Вход по чужой прямой ссылке не раскрывает данные.

Исправлены несовпадения: изменение порядка у читателей, приостановка проекта без полномочия, команды решений по обращениям, подготовка/запуск автоматизации, команды Jira/замечаний/заключения, отображение уведомлений и человеческих экранов сервисной записи. Существующие задачи без рассчитанного приоритета видны в общей очереди. Приостановка требует реальной причины и ссылки на инцидент; старая нерабочая команда возобновления с придуманными основаниями не отправляется. Возобновление по-прежнему требует точных серверных оснований и независимого согласования.

Источники проверки: `live-access.json` — ответы API для всех 12 персон; `live-ui.json` — проход по меню и запрещённой прямой ссылке каждой персоны, состояние команд карточки. Браузерные регрессии 013/014/016/017 проверяют ввод, мобильный экран, историю, список Hermes и роль каждой кнопки. В текущей базе QA-запросы есть только в ALPHA; одновременные задачи ALPHA/BETA проверены в браузерной фикстуре, серверные права обоих QA на BETA проверены в PostgreSQL и на живом API.
