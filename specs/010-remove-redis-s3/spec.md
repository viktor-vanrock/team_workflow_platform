# Feature Specification: Упрощение первой версии без Redis и S3

**Feature Branch**: `main`

**Created**: 2026-09-07

**Status**: Draft

**Input**: User description: "Если S3 и Redis не нужны, не добавлять их в первую версию продукта и вычистить их через новую задачу Spec Kit."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Запуск продукта без лишней инфраструктуры (Priority: P1)

Как разработчик или оператор первой версии, я хочу запускать весь локальный и целевой контур без Redis и S3-совместимого хранилища, чтобы уменьшить число обязательных сервисов, настроек, секретов и отказов.

**Why this priority**: Это непосредственно реализует решение о границе первой версии и снижает стоимость разработки, развёртывания и сопровождения.

**Independent Test**: Чистый контур запускается только с обязательными сервисами, проходит readiness и выполняет основной QA flow при полном отсутствии Redis и S3 endpoint.

**Acceptance Scenarios**:

1. **Given** чистая среда без Redis и S3, **When** оператор запускает первую версию по документированной процедуре, **Then** API, worker и web становятся готовыми без отсутствующих зависимостей.
2. **Given** работающее приложение без Redis, **When** создаётся и обрабатывается фоновая работа, **Then** она надёжно проходит через существующее долговечное состояние и восстанавливается после перезапуска worker.
3. **Given** конфигурация первой версии, **When** оператор проверяет обязательные параметры и секреты, **Then** в них отсутствуют параметры Redis и S3.

---

### User Story 2 - QA evidence без встроенного объектного хранилища (Priority: P1)

Как QA-пользователь, я хочу продолжать фиксировать наблюдения, результаты, evidence manifest и verdict без обязательной платформенной загрузки бинарных файлов, чтобы основной QA flow не зависел от S3.

**Why this priority**: Удаление S3 не должно разрушить основную ценность первой версии — проверяемый QA lifecycle и человеческое заключение.

**Independent Test**: Ручная или автоматическая QA-сессия завершается с evidence-метаданными, review и verdict без обращения к объектному хранилищу; доступные CI-артефакты читаются из GitLab в пределах утверждённой политики.

**Acceptance Scenarios**:

1. **Given** ручная QA-сессия без бинарных вложений, **When** исполнитель записывает результаты и передаёт сессию на review, **Then** manifest, review и verdict создаются без S3.
2. **Given** автоматическая сессия с доступным GitLab artifact, **When** пользователь просматривает разрешённый артефакт, **Then** платформа читает его из GitLab и не создаёт платформенную S3-копию.
3. **Given** пользователь пытается загрузить локальное бинарное вложение, **When** он использует первую версию продукта, **Then** недоступная возможность не показывается и не обещается публичным контрактом.

---

### User Story 3 - Однозначная документация и поставка (Priority: P2)

Как владелец продукта или инженер внедрения, я хочу видеть одну непротиворечивую границу первой версии, чтобы не заказывать Redis, buckets, IAM и связанные эксплуатационные процедуры.

**Why this priority**: Даже после удаления runtime-зависимостей устаревшая документация может привести к лишним инфраструктурным работам и ошибочной приёмке.

**Independent Test**: Актуальные архитектурные документы, шаблоны конфигурации, deployment checklist и dependency inventory не требуют Redis или S3 для первой версии и прямо описывают GitLab-only artifact mode.

**Acceptance Scenarios**:

1. **Given** комплект документов первой версии, **When** команда инфраструктуры формирует среду, **Then** она не получает требований на Redis, S3 endpoint, bucket, credentials, backup или lifecycle.
2. **Given** CI и dependency inventory, **When** выполняется проверка поставки, **Then** в runtime graph отсутствуют Redis/BullMQ и S3/S3Mock компоненты.

### Edge Cases

- Фоновая работа остаётся в промежуточном состоянии во время перезапуска worker: после запуска она должна быть обнаружена по долговечному состоянию и продолжена без повторного внешнего эффекта.
- Неопределённый результат внешней записи: восстановление должно использовать прежний idempotency/effect key и подтверждение у владельца внешнего состояния.
- Историческая ссылка на S3-объект существует только в локальных fixture-данных: первая версия не обязана мигрировать или обслуживать эти непроизводственные bytes, но не должна ошибочно считать их поддерживаемым продуктовым сценарием.
- Evidence manifest не содержит бинарных вложений: он остаётся допустимым, если обязательные наблюдения, результаты, provenance и человеческий review присутствуют.
- GitLab artifact истёк: metadata, checksum и audit сохраняются, availability становится недоступной согласно существующей политике.
- Redis- или S3-переменные случайно остались в окружении: они не должны активировать скрытый runtime-контур или влиять на readiness.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Первая версия MUST запускаться и считаться готовой при полном отсутствии Redis.
- **FR-002**: Фоновая обработка MUST использовать существующее долговечное состояние как единственный источник истины и MUST восстанавливаться после перезапуска без Redis.
- **FR-003**: Первая версия MUST запускаться и считаться готовой при полном отсутствии S3 или S3-совместимого сервиса.
- **FR-004**: Первая версия MUST NOT требовать Redis/S3 endpoints, credentials, buckets, volumes, health checks или lifecycle policy.
- **FR-005**: Платформенная загрузка и хранение произвольных бинарных QA-вложений MUST быть исключены из первой версии и не должны рекламироваться пользователю.
- **FR-006**: QA observations, result history, evidence manifests, reviews, signatures, audit и verdicts MUST продолжать работать без бинарных вложений.
- **FR-007**: CI artifact bytes MAY оставаться у авторитетного CI provider; разрешённое чтение MUST сохранять project scope, entitlement, classification, checksum, provenance и availability checks.
- **FR-008**: Первая версия MUST NOT автоматически копировать CI artifacts во внутреннее объектное хранилище.
- **FR-009**: Актуальные product, architecture, deployment, runbook и configuration документы MUST описывать один GitLab-only artifact mode и отсутствие Redis/S3.
- **FR-010**: Runtime dependency inventory MUST исключать Redis/BullMQ и S3/S3Mock реализации, используемые только удаляемым контуром.
- **FR-011**: Существующие гарантии idempotency, outbox/inbox, audit, Workspace/Project isolation и запрета production effects MUST сохраниться.
- **FR-012**: Автоматические проверки MUST доказывать запуск, readiness, основной QA flow, restart recovery и artifact behavior без Redis/S3.
- **FR-013**: Изменение архитектурного решения MUST быть отражено отдельным ADR и во всех текущих документах, которые определяют границу первой версии.
- **FR-014**: Исторические feature-документы MAY сохраняться как история решений, но MUST быть явно superseded там, где они требуют Redis/S3 для текущей первой версии.

### Key Entities

- **Durable Work Record**: Существующая запись фоновой работы, содержащая scope, состояние, lease, idempotency и данные восстановления.
- **Artifact Reference**: Метаданные внешнего CI-артефакта с owner, scope, checksum, provenance и availability; не означает владение платформой бинарными bytes.
- **Evidence Manifest**: Неизменяемое описание QA evidence, которое может состоять из наблюдений, результатов и ссылок на доступные внешние артефакты без обязательного бинарного вложения.
- **First-Version Deployment Profile**: Утверждённый набор обязательных сервисов и параметров, в котором отсутствуют Redis и S3.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Чистый локальный контур достигает готовности со 100% отсутствием Redis- и S3-сервисов.
- **SC-002**: Все обязательные сценарии первой версии проходят без Redis/S3 endpoints и credentials.
- **SC-003**: Перезапуск worker во время фоновой работы не теряет ни одной долговечной команды и не создаёт повторного внешнего эффекта во всех проверяемых recovery-сценариях.
- **SC-004**: Ручной QA flow без вложений и автоматический QA flow с GitLab-hosted artifact оба завершаются успешно.
- **SC-005**: В актуальных deployment inputs отсутствует 100% Redis/S3 параметров, секретов, volumes и health requirements.
- **SC-006**: Runtime dependency inventory и production package graph содержат 0 Redis/BullMQ и S3/S3Mock runtime implementations.
- **SC-007**: Проверка актуальной документации не находит ни одного утверждения, что Redis или S3 обязательны для первой версии.

## Assumptions

- Решение относится к первой версии и не запрещает отдельную будущую feature по добавлению очереди или объектного хранилища после измеренной необходимости.
- Первая версия использует уже существующую долговечную модель фоновой работы; отдельный новый брокер не добавляется.
- GitLab является единственным поддерживаемым владельцем бинарных CI artifacts в первой версии.
- Ручные бинарные attachments не входят в первую версию; текстовые наблюдения, результаты, manifests, review и verdict остаются.
- Производственных S3-данных ещё нет, поэтому перенос пользовательских bytes не требуется.
- Generic artifact metadata и provider-neutral access boundaries могут оставаться, если они нужны для GitLab artifacts и не влекут S3 runtime dependency.
- Изменение не ослабляет Workspace/Project authorization, classification, audit, idempotency и human-verdict требования.
