**Scope:** только feature `002`; real Jira/GitLab/Mattermost, full Hermes runtime, production deployment, reusable TMS и queue/SLA не входят.

## Правила исполнения

- Формат задачи: `- [ ] Txxx [P?] [USn?] действие + точный repo-relative путь`.
- `[P]` означает file-disjoint работу, которую можно выполнять параллельно только после общих prerequisites текущей фазы.
- `[US1]`…`[US5]` соответствуют `US-001`…`US-005` из [spec.md](spec.md). Setup/foundation/hardening задачи story label не имеют.
- Нумерация feature-local и непрерывная. Все checkbox изначально `[ ]`; `[x]` ставится только после фактической проверки с указанной командой/evidence.
- Test-authoring task закрывается после доказанного ожидаемого `RED`. Acceptance считается `GREEN` только после story checkpoint и снова в финальном gate.
- Feature 001 является hard prerequisite. Нельзя реализовывать локальные обходы Command Gateway, exact Approval, artifact proxy, confirmation UoW, audit или Mock Hub только ради 002.
- QA semantics живёт только в `competency-qa`. Platform Core не получает `TestSession`, `Finding`, `EvidenceManifest`, `QaVerdict`, QA enum/rule/action branch.
- Каждый QA aggregate, row, event, job, action, command и artifact link несёт `workspaceId + projectId`. Deny выполняется до repository child lookup, storage/model/queue/Broker/Connector call.
- Каждая external write проходит typed Pack action → Command Gateway → policy/Approval → PostgreSQL outbox → worker → Broker → Connector и использует стабильный effect key.
- Human-only decisions валидируют verified actor type, live role/entitlement/classification и pinned policy; строка роли из request body никогда не является authorization basis.
- Every Pack operation registration/use case declares one closed guard class. `AGGREGATE_MUTATION` invokes the installed invalidator and terminally invalidates any predispatch completion candidate before changing candidate inputs; `COMPLETION_SELF_TRANSITION` revalidates and advances only the exact unchanged candidate without self-invalidation; completion-in-flight denies aggregate work but permits that candidate's terminal reconciliation; Core DONE permits only idempotent confirmed replay/read and the explicitly classified post-close clerical correction.
- Signed evidence/verdict и published policy/context append-only. Correction создаёт новую revision; historical rows не обновляются.
- После задачи исполнитель обновляет checkbox и добавляет к checkpoint команду, environment и краткий PASS evidence.
