# Как работать в локальном интерфейсе

Полное [руководство пользователя](../user-guide/README.md) содержит описания ролей,
[инструкции для заказчика и команды QA](../user-guide/daily-work.md),
[администрирование и сопровождение](../user-guide/administration.md), а также
ограничения текущего интерфейса и порядок действий через API.

Откройте http://localhost:55173 после `pnpm dev:pilot:up`.

## Оформление «Чёрный орден»

Рабочее пространство оформлено как «Архив ордена»: угольные панели, книжные заголовки,
тёплые металлические линии и бордовые основные кнопки. Это единая тема для входа,
запросов, очереди, проектов и дополнительных разделов; переключать её не требуется.

Названия действий и порядок работы сохранены. Предупреждения и ошибки имеют явные
подписи, а рекомендации Hermes по-прежнему требуют решения человека. Фокус клавиатуры
выделен светлой рамкой; на узком экране меню переносится над содержимым. Оформление
и шрифты загружаются в составе платформы и не требуют внешних ресурсов.

## Выберите роль

На первом экране выберите роль и нажмите «Начать работу». Под списком написано, для чего подходит выбранная роль. Доступ определяется назначениями в рабочей области и проектах; сервер проверяет права на каждое действие. Первый успешный локальный вход однократно выбирает глобального администратора — [порядок первого входа](../deployment/upgrade-and-verification.md).

| Роль                  | Для чего                                               |
| --------------------- | ------------------------------------------------------ |
| Заказчик              | Описать и отправить запрос на проверку                 |
| Исполнитель QA · QA 1 | Подготовить и выполнить проверки, сохранить результаты |
| Руководитель QA       | Управлять очередью, согласовать решения и результаты   |
| Администратор         | Настроить подключения и готовность проекта             |
| Читатель              | Просматривать проекты без изменения данных             |

QA 1 и QA 2 имеют одну роль исполнителя для всех проектов. Глобального рабочего проекта нет: очередь и запросы общие, проект указан на каждой задаче. «Сменить роль» возвращает к выбору и очищает предыдущую рабочую область. Переходы по меню сохраняют вход; обновление страницы требует повторного входа.

## Создайте запрос

1. Откройте «Новый запрос» и выберите доступный проект.
2. Укажите понятное название и вид проверки. У каждого вида есть объяснение.
3. Заполните известные цель, область и ожидаемый результат. Дополнительные сведения необязательны; отсутствие сведений не означает отсутствие блокирующих факторов.
4. Нажмите «Проверить запрос». Черновик сохранится, но ещё не уйдёт команде.
5. Проверьте резюме. «Изменить» возвращает к форме и требует сохранить обновлённый черновик.
6. Нажмите «Отправить запрос». Во время обработки повторять отправку не нужно.
7. Дождитесь «Запрос создан» и нажмите «Открыть запрос».

Если обработка затянулась или пропало соединение, используйте «Проверить состояние». Неизвестный результат не означает, что запрос не был создан. Не закрывайте страницу до проверки результата; список восстановления всех черновиков в текущем API отсутствует.

## Продолжите работу

«Запросы» содержит подтверждённые заявки всех доступных проектов рабочей области. Выберите нужную по названию. В карточке показаны текущие состояния и следующий шаг.

- «Статус в Jira» — рабочий процесс, исполнитель и сроки.
- «Готовность» — достаточно ли данных и ресурсов для проверки.
- «Проверки» — отдельные сеансы выполнения.
- «Материалы» — наблюдения и подтверждающие сведения.
- «Замечания» — найденные проблемы и дефекты.
- «Заключение» — итог QA, подписываемый человеком.

Заключение QA не является решением о выпуске. Отдельные действия требуют роли исполнителя или руководителя; создание запроса не выдаёт права на их выполнение.

## Другие разделы

«Очередь» показывает этапы и порядок доступной работы. «Проекты» — подключения и состояние настройки. Пустой или начальный проект не считается готовым автоматически.

Заказчик может [создать проект с Hermes](../user-guide/customer-projects.md).
Администратор или регистратор использует «Проекты → Новый проект» и редактирование
карточки. Глобальный администратор назначает роли в «Пользователи и доступы».
Писатели и их лид работают в [отдельной области документации](../user-guide/tech-writing.md).

«Как работать» содержит краткую справку внутри приложения. «Дополнительно» открывает интеграции и диагностику. «Инструменты разработки» содержит прежние Dummy/Mock Hub операции и не нужен для обычного создания QA-запроса.

Глубокие административные формы по-прежнему рассчитаны на администратора и используют версионированные конфигурации. Корпоративные pilot-экраны имеют собственную авторизацию.

Изменения Spec Kit 017: глобальный выбор проекта удалён; контекст карточки определяется её ссылкой. «Владелец рабочей области» и «Администратор интеграций» объединены в «Администратор», «Читатель» и «Наблюдатель» — в «Читатель». Эти старые имена могут встречаться только в исторических записях. Права действий проверяются для проекта открытой сущности.
