## Текущий состав

TypeScript monorepo: NestJS API и worker, React/Vite web, PostgreSQL/TypeORM,
статически подключаемые competency packs и connectors. Полный локальный Compose
включает QA, отдельную область технической документации, управление доступами,
создание и редактирование проектов, диалоги заказчика с Hermes и эмуляторы
Jira/GitLab/Mattermost. Очередь и запросы объединяют доступные проекты области;
заказчик видит только проекты с действующим проектным назначением.

В v1 PostgreSQL хранит состояние и очереди; бинарные CI-артефакты остаются в GitLab.
Redis, S3 и MinIO не нужны. Первый локальный и первый корпоративный администраторы
выбираются независимо при успешном входе; выбор сохраняется после перезапуска.

Для новой установки готов [один QA workspace для приёма проектов](deployment/initial-qa-workspace.md):
отдельный образ, bootstrap, корпоративный вход, пользователи и карточки проектов.
Корпоративная сессия, администрирование и подключаемый onboarding существуют,
но полный корпоративный QA API/worker и доставка release images ещё требуют
работ по 008/T025. Семь открытых обязательств 008 и порядок допуска перечислены
в [комплекте деплоя](deployment/README.md).

## Как поддерживать документы

При изменении поведения обновляйте README, соответствующее руководство и runbook.
Команды сверяйте с [package.json](../package.json), настройки — с parser и Compose,
версии схем — с `runtimePersistence(composition).expectedVersions`. Для архитектурного
каталога выполните `node docs/architecture/generate-inventory.mjs`; порядок обновления
HTML/SVG указан в [архитектуре](architecture/README.md#13-полнота-исходники-и-проверка-схемы).

`specs/` содержит проектные требования, планы и доказательства отдельных изменений;
`docs/audits/` — датированные проверки. Исторические отчёты не переписываются под
новую версию и не заменяют повторную проверку текущего стенда.
